## 标准只读查询脚本与输入要求

官方文档入口：[查询API调用次数](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/openApi-mgnt/getApiQuota.html)。用户提供的截图明确展示接口名getApiQuota、服务端HTTPS POST地址，以及“本接口不支持云调用”。截图已作为用户提供的一手资料核对，没有重新访问被拦截的站点。

目标查询参数已经固定：

```json
{"cgi_path":"/wxa/msg_sec_check"}
```

脚本位于scripts/wechat-quota.cjs，npm入口为quota:query。只访问固定的官方quota/get路径，目标固定为msgSecCheck；单次请求、15秒超时、禁止重定向、不自动重试，不获取token或执行清零。凭据仅从WECHAT_ACCESS_TOKEN环境变量或标准输入读取，不接受命令行token、不打印URL或原始错误。响应只保留计数和数字限频字段。

离线查看请求：

```bash
npm run quota:query -- --plan
```

在具有正常访问权限和合法服务端凭据的环境，可使用--query进行一次查询；当前Agent环境没有执行该模式，也没有搜索浏览器或本机凭据以绕过站点限制。截图明确不支持云调用，现有cloud.openapi免token路径不能直接代替HTTPS调用；向云函数配置增加一个方法名也不能改变这一接口能力。

已取得的响应可以用--response FILE --observed-at ISO离线解析，必须显式提供原采集时间。目标quota字段为daily_limit、used、remain；缺失或非法值会报错，不能按0处理。即使算术吻合，也保留account_identity_verified、counting_scope_verified、reset_rule_verified为false，不将token所属账号、共享范围或重置规则写成已证明。

即使取得三个计数值，也不能据此补写平台没有说明的共享范围、失败调用扣减或重置时间。需要额外的官方规则或同账号平台支持答复；不会用耗尽配额、清零或大量调用做实验。
