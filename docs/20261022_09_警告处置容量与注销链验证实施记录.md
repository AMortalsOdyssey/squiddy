# 警告处置、容量与注销链验证实施记录

## TL;DR

- 0.5.1将调试基础库从灰度3.17.4固定为已发布3.17.3。原11条控制台警告已逐条分类；开发工具的热重载、预加载和worker提示保留，不通过隐藏日志宣称清零。
- 真实开发云完成80道菜、30条成员记录、40场同时进行的饭局读取。30人参与的饭局包含29份点菜记录、30道菜、合计870份请求，重复读取均成功；成员与部分饭局为明确标记的受控数据，不是30人真实协作。
- 容量测试复现并修复JSON整包导出的3秒超时。现按每次一场读取，在客户端汇总；真实页面已生成2,010,601字节JSON，含两个厨房的41场饭局，无重复。
- 大文件验证另发现2077KB的setData警告及selectable弃用提示。页面改为最多4096字预览，完整文件与复制内容保留；离页或注销清除内存中的完整文本。
- 新增完整运行时注销测试，覆盖立即撤权、共享图片保留、私人记录删除、文件删除失败阻塞完成及恢复后最终完成。平台身份与审核使用替身，文件读写与运行时代码真实执行；当前没有真实测试账号，真实身份注销验收仍未闭环。
- 微信提醒、多人真机和提审继续暂缓；没有开通付费、变更数据库访问规则或增加客户端管理权限。

## 部署范围与数据边界

沿用现有免费开发云、四个函数、Nodejs20.19及3秒时限。本次业务变更在api部署；其他函数没有需要重新部署的行为变更。维护触发器仍是原每5分钟一次，本轮未修改。0.5.1只上传开发版本，不提审或正式发布。

容量数据位于单独创建的技术厨房。80道菜与最初7场饭局经真实微信SDK、实际接口、内容审核及数据库事务创建；后续33场饭局和29名成员由受控管理员流程补入，并核对权限关系。没有将受控成员写成真实微信身份，也没有为测试伪造getWXContext或开放维护入口。

| 原始数量 | 来源与含义 | 处理及结论 |

| 1 | 使用灰度基础库3.17.4 | 原生项目设置选择已发布3.17.3，配置模板同步固定版本；未关闭域名、TLS或证书校验 |

| 2 | WAAutoService.js及WAServiceMainContext.js预加载后暂未使用 | 文件来自开发工具本地调试资源，3.17.3初次编译仍出现；应用源码不生成这两个preload，不修改微信框架脚本 |

切换后最初观察为2条预加载警告、0个错误。保存代码会继续累加热重载提示；不能把某一刻的警告数量当作固定产品指标。本轮另有一次验证脚本使用旧wx.getFileInfo产生弃用提示，产品代码没有使用该接口。

启动文件清理不再同步遍历和删除缓存，注销时仍立即清理本地缓存。新增回归确认旧图片回收不阻塞启动、不误删新图片、保留备份ZIP。云SDK仍在首次业务调用前初始化，其约51ms的模拟器开销保留记录。

大文件导出暴露的setData与selectable提示属于应用代码，已经修复。文件仍写入完整JSON；页面仅渲染开头4096字并明确说明预览边界。完整字符串放在页面实例的私有字段，不通过setData传送。复制仍使用完整字符串，失败有提示；页面隐藏、卸载或账号注销均清除私有字符串。

| 历史与ZIP备份分页 | 实际历史单页20条，菜谱备份10条，饭局备份1条，均可读 | 45条历史及新增历史后的稳定游标另有隔离回归；不冒充这批云数据已有45场 |
| 同时40场后有效第41场请求 | 被微信内容审核45009拒绝，不能据此声称云端40场规则已验收 | 本地回归确认40场拒绝、结束一场释放额度；真实有效发布与释放后再次发布仍待审核额度恢复 |
| 30人加入与第31人 | 隔离业务测试确认31人被拒绝、事务不残留、离开后新成员可加入、旧备注立即隐藏 | 身份为测试替身，真实31账号加入未开展 |

创建第8场饭局时，私有audit_events记录了operation=openapi.security.msgSecCheck、provider_code=45009。间隔后重试仍出现；分钟限制还是日额度在本轮未获得权威额度回读，因此不写具体恢复时间。

云运行时现在将45009明确返回CONTENT_RATE_LIMITED及“内容审核已达平台调用限制，请稍后再试”。同时保留脱敏诊断码；不误报成内容违规，不自动重试，不绕过审核。真实SDK已回读到新提示。替身测试覆盖SDK抛错与非零返回值两种形式，并确认拒绝前不写业务、额度恢复后同请求可以成功。

## JSON导出的超时已改为有界分页

故障路径为settings.exportData → export.mine → 逐场读取全部历史。满容量时真实平台返回-504003、Invoking task timed out after 3 seconds；小样本成功不能覆盖这个问题。

service.js的export.mine新增profile与meals两种section。profile只返回本人及当前可访问厨房的元信息；meals复用现有备份读权限，每次最多一场，并再次鉴权。客户端personal-export.ts循环读取后生成原JSON结构，保留昵称、收藏与可访问饭局。普通成员不能获得厨师内部价或他人备注。

旧的不分页请求在多场数据下明确返回EXPORT_PAGINATION_REQUIRED，避免旧客户端反复等待超时。超过2Mi字的JSON汇总明确停止并建议使用可分卷的厨房备份，不生成“完整导出”假象。重复游标或离页均停止后续读取。分页导出按各次读取时状态生成，不是原子时间点快照。

真实页面产物包含原厨房1场及技术厨房40场，每间厨房内饭局ID无重复，技术厨房40场各有30道菜单；文件SHA256为2703591c44cbd5ecd1e03bc3ee0386acf5615d913b8712a721d386d3224c7718。记录只公布校验值及数量，原始JSON不进入仓库。

## 注销链的验证层次

| 层次 | 本轮证据 | 结论 |
|---|---|---|
| 真实现用主人身份 | SDK调用account.delete被OWNER_TRANSFER_REQUIRED拒绝 | 主人保护真实生效；现用账号与原厨房未删除 |
| 开发工具身份清单 | CLI真实测试账号列表为空，原生多账号面板显示“真实测试账号：暂无可用测试号”；另列虚拟测试账号 | 不能用虚拟账号冒充真实身份注销，不能为了验收删除现用主人 |
| 完整运行时代码与真实本地文件 | API准备两张JPEG并经模拟回调；一张绑定共享厨房、一张无引用；注销后立即拒绝业务并隐藏个人选择；注入删除失败时状态不完成；恢复删除后完成，私人资料/选择/反馈/回执清除，共享图逐字节不变且可读 | 代码与文件故障恢复链闭环；身份、审核、平台触发与云文件API为替身，不等于真实微信账号到真实云存储的全链验收 |
| 原生页面处理器 | 既有页面注销流程及新增导出离页清理回归通过 | 是页面代码执行，不是多人手机验收 |
