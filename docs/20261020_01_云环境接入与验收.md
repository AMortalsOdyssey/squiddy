# 云环境接入与验收

## TL;DR

- 四个云函数已在微信免费开发环境完成部署；单账号云端主流程与客户端数据隔离已验证。最新0.5.0范围、19页与备份恢复边界见 [备份恢复与长期使用完善](20261021_08_备份恢复与长期使用完善实施记录.md)。
- 通用业务只认 `getWXContext()` 身份，客户端不能指定用户或角色。公开摘要使用单独的最小字段接口。
- 数据库、存储默认拒绝客户端直读写；审核回调和定时任务还必须禁止客户端调用。
- 图片审核和通知缺少真实配置时拒绝或禁用，不以模拟结果放行正式内容。
- 以下步骤用于其他环境的接入；实际环境身份与密钥保留在本地及云平台，不随仓库分发。正式发布仍是独立步骤。

## 部署坐标

| 函数             | 调用者               | 职责                                           |
| ---------------- | -------------------- | ---------------------------------------------- |
| api              | 已登录的本小程序用户 | 业务读写、内容审核、私有图片地址               |
| publicRead       | 分享访客             | 只返回主动公开的标题和菜名                     |
| platformCallback | 可信平台事件         | 保存图片审核回调并应用结果                     |
| maintenance      | 平台定时触发器       | 分批删除、图片回收、回调补偿、通知、记录保留期 |

所有函数使用同一环境，均配置 `SQUIDDY_APP_ID`。`npm run build` 复制共享源码；`npm run setup:cloud` 安装锁定依赖。本次使用 Node.js 20.19；sharp 要求 Node.js 20.9 或更新的兼容版本。先在平台创建正确运行时，再部署代码，避免旧 CLI 默认创建不可改运行时的 Node.js 16 函数。执行 `npm run prepare:cloud` 生成 Linux 部署目录，再用 CLI 的 `--paths` 上传且不加 `--remote-npm-install`。不能把 macOS 的 `node_modules` 打包上传。图片函数依赖 `sharp` 的 Linux 二进制，必须以真实云调用证明可加载。

## 接入顺序

1. 选择已授权的开发环境，确认报价、资源限额与成本控制。此仓库不代办付费。
2. 按 `cloud/collections.json` 创建所有集合。CloudBase 使用文档键：随机资源键和 SHA256 关系键；确定性关系键保证成员与选择不重复。这不是通用 MongoDB ObjectId 的迁移模板。
3. 每个集合应用 `cloud/database.rules.json`；存储应用 `cloud/storage.rules.json`。逐项回读并用普通客户端直读写测试证明被拒绝。
4. `cloud/function-access.json` 是安全核对清单，不能直接当作当前平台配置格式。当前 OPA 规则用于 HTTP 调用路径，不能与旧版函数规则等同；本次没有启用 HTTP 网关。微信调用仍须由函数检查 SDK 身份与可信来源。实测普通客户端调用 `platformCallback` 和 `maintenance` 返回 `FORBIDDEN`。
5. 设置环境变量。`SQUIDDY_INVITE_KEY` 由密码学随机数产生，至少32字符，保存在云平台秘密配置中；不得放在小程序包或仓库。更换它会使旧请求无法重新派生邀请口令，因此轮换前应先撤销旧邀请。
6. 部署四个函数，保留每个部署版本、代码SHA、环境与验证结果。配置 maintenance 的平台定时触发器。每次只处理有限批次并保存游标；仓库提供每五分钟一次的触发配置，须按实际配额调整并单独验证平台执行回执。免费环境单次执行限3秒，维护任务使用1.8秒软时间预算及表间轮转，单个网络请求仍可能超时。记录中的“正在删除”不能写成已经删除。
7. 微信 OpenAPI 权限来自函数 `config.json`；若出现 `-604101`，在开发者工具中增量上传该配置并复测，不能跳过内容审核。定时器还需使用“上传触发器”操作。
8. 填 `config/local.json` 的 AppID、环境ID，并切 `mode` 为 `cloud` 后构建。客户端没有演练回退逻辑。

## 图片审核的真实进入条件

`SQUIDDY_MEDIA_ENABLED` 默认 `false`。本轮开发环境已启用，真实新图从提交推进到approved，且微信SDK成功解码私有图片。正式环境须重新核对以下条件，不照搬开发配置：

- 平台把 `wxa_media_check` 事件送到已隔离的 callback 函数。`SQUIDDY_CALLBACK_SOURCE` 必须来自该平台实际可信上下文观测，不能猜值；本轮真实来源为`wx_callback`，它正常携带OPENID；代码只对这个来源接纳OPENID，仍拒绝FROM_APPID、`wx_client`链或HTTP来源，并核对SDK与事件APPID。
- 不把 `wx_trigger` 当作消息回调来源：它用于定时任务。未知回调入口保持关闭，并在联调时根据官方协议做适配。
- 已验证 `msgSecCheck`、`mediaCheckAsync` 权限和真实返回结构；本轮正常图片和超时后状态回读有真实证据，拒绝、重复回调及回调早于入库有自动测试；正式前仍需补对应真实故障演练。
- 私有原图被解码、限制像素、缩放为 JPEG 并移除 EXIF/GPS；待审图片不能绑定菜谱或获取展示地址。
- 上传前通过官方SDK取得文件ID并登记持久预约；上传后登记前中断也能回收。注销与上传并发时保留预约，文件队列结束才完成注销；不存在文件的SDK错误按幂等成功处理。真实云中断状态、历史引用保留、两阶段回收和删除恢复证据见07号演练记录。没有声称强杀平台进程。

图片显示通过`media.content`逐次鉴权并返回审核后的JPEG内容，客户端不需要开放存储权限或关闭域名检查。编码结果最多512KiB；本机渲染缓存随启动和账号停用清理。免费3秒调用超时时先读原上传任务，不直接重放。

审核回调先写入持久收件表，maintenance 会在 trace 建立后补应用，避免过早回调丢失。结果只允许把 pending 图片推进到审核终态，旧回调不能覆盖终态。

## 通知与分享

当前账号真实查询的订阅类目和模板均为空，用户本轮决定暂缓微信提醒，保留页面进度。模板未配置时，profile 明确返回不可用。开通时配置实际模板 ID 和标题、状态字段名，并逐项核对该账号模板字段类型与长度。用户拒绝订阅不影响业务；未知发送结果标为 unknown，不自动重发。已发出的提醒不能因撤销上桌状态而收回。

朋友邀请使用服务端 HMAC 口令、哈希存储、到期和撤销检查。持有邀请需要先确认加入；公开摘要只含标题和菜名，不提供成员、地址、时间、备注或价格。海报页面与 getUnlimited 接口已接线；SQUIDDY_POSTER_ENABLED 默认关闭，启用前需确认发布路径和 SQUIDDY_CODE_ENV。scene 使用24字符公开分享短码，不含邀请口令。0.4.0已在真实开发云生成并在原生海报中显示开发版小程序码；朋友圈入口与真实手机扫码仍需账号能力和双端验收；本地海报明确没有扫码凭据。

## 备份与恢复

0.5.0补上用户ZIP备份与新厨房菜谱恢复；运营侧新增加密备份、due和健康命令。使用方法、文件/密钥保管、真实验证与未安装调度的边界统一见08号记录。以下为整库逻辑采集与隔离恢复，不等同用户导入。

个人导出经过权限过滤，不等于整库恢复。完整操作工具支持数据库文档与原始附件的私有逻辑备份：

```sh
node scripts/cloud-backup.cjs capture artifacts/NEW-private-backup
node scripts/cloud-backup.cjs verify artifacts/NEW-private-backup/archive-private.json
node scripts/cloud-backup.cjs plan ARCHIVE PRIVATE-file-map.json NEW-private-plan.json
node scripts/cloud-backup.cjs apply PLAN squiddy_restore_YYYYMMDD NEW-private-state.json
```

使用已登录的官方wechatide CLI与本机明确云配置；必要时用WECHATIDE_BIN指定官方CLI路径。capture先后读取两遍集合与文档，内容变化即停止，再下载引用文件并校验。该方法证明采集窗口内观察一致，不承诺平台原子时间点快照。输出及原始回执为私有文件，不提交仓库。

plan要求附件已上传到独立恢复目录，并提供经过回读的文件ID映射。apply只写隔离集合，仅补缺失记录，已有记录不一致则停止，不覆盖业务集合。异步确认任务保留私有状态，继续时先查旧任务与实际结果。v1离线backup/restore仍保留兼容。

本轮真实云完成25个集合、51条文档、4张图片的备份与独立恢复；分段中断续传、缺失记录补回、冲突拒绝和附件哈希有独立回执。详细边界与收尾见[故障演练记录](20261021_07_图片清理与云备份恢复故障演练实施记录.md)。在线覆盖、运行时切换、平台时间点回档与大规模容量并未测试。
