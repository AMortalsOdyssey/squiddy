# 云环境接入与验收

## TL;DR

- 四个云函数已在微信免费开发环境完成部署；单账号云端主流程与客户端数据隔离已验证。最新0.3.0范围、16页检查及开发云回执见 [全页紧凑检查与参考功能补全](20261021_05_全页紧凑检查与参考功能补全实施记录.md)。
- 通用业务只认 `getWXContext()` 身份，客户端不能指定用户或角色。公开摘要使用单独的最小字段接口。
- 数据库、存储默认拒绝客户端直读写；审核回调和定时任务还必须禁止客户端调用。
- 图片审核和通知缺少真实配置时拒绝或禁用，不以模拟结果放行正式内容。
- 以下步骤用于其他环境的接入；实际环境身份与密钥保留在本地及云平台，不随仓库分发。正式发布仍是独立步骤。

## 部署坐标

| 函数             | 调用者               | 职责                                           |
| ---------------- | -------------------- | ---------------------------------------------- |
| api              | 已登录的本小程序用户 | 业务读写、内容审核、私有图片地址               |
| publicRead       | 分享访客             | 只返回主动公开的标题和菜名                     |
| platformCallback | 可信平台事件         | 保存图片审核回调并应用结果                     |
| maintenance      | 平台定时触发器       | 分批删除、图片回收、回调补偿、通知、记录保留期 |

所有函数使用同一环境，均配置 `SQUIDDY_APP_ID`。`npm run build` 复制共享源码；`npm run setup:cloud` 安装锁定依赖。本次使用 Node.js 20.19；sharp 要求 Node.js 20.9 或更新的兼容版本。先在平台创建正确运行时，再部署代码，避免旧 CLI 默认创建不可改运行时的 Node.js 16 函数。执行 `npm run prepare:cloud` 生成 Linux 部署目录，再用 CLI 的 `--paths` 上传且不加 `--remote-npm-install`。不能把 macOS 的 `node_modules` 打包上传。图片函数依赖 `sharp` 的 Linux 二进制，必须以真实云调用证明可加载。

## 接入顺序

1. 选择已授权的开发环境，确认报价、资源限额与成本控制。此仓库不代办付费。
2. 按 `cloud/collections.json` 创建所有集合。CloudBase 使用文档键：随机资源键和 SHA256 关系键；确定性关系键保证成员与选择不重复。这不是通用 MongoDB ObjectId 的迁移模板。
3. 每个集合应用 `cloud/database.rules.json`；存储应用 `cloud/storage.rules.json`。逐项回读并用普通客户端直读写测试证明被拒绝。
4. `cloud/function-access.json` 是安全核对清单，不能直接当作当前平台配置格式。当前 OPA 规则用于 HTTP 调用路径，不能与旧版函数规则等同；本次没有启用 HTTP 网关。微信调用仍须由函数检查 SDK 身份与可信来源。实测普通客户端调用 `platformCallback` 和 `maintenance` 返回 `FORBIDDEN`。
5. 设置环境变量。`SQUIDDY_INVITE_KEY` 由密码学随机数产生，至少32字符，保存在云平台秘密配置中；不得放在小程序包或仓库。更换它会使旧请求无法重新派生邀请口令，因此轮换前应先撤销旧邀请。
6. 部署四个函数，保留每个部署版本、代码SHA、环境与验证结果。配置 maintenance 的平台定时触发器。每次只处理有限批次并保存游标；仓库提供每五分钟一次的触发配置，须按实际配额调整并单独验证平台执行回执。免费环境单次执行限3秒，维护任务使用1.8秒软时间预算及表间轮转，单个网络请求仍可能超时。记录中的“正在删除”不能写成已经删除。
7. 微信 OpenAPI 权限来自函数 `config.json`；若出现 `-604101`，在开发者工具中增量上传该配置并复测，不能跳过内容审核。定时器还需使用“上传触发器”操作。
8. 填 `config/local.json` 的 AppID、环境ID，并切 `mode` 为 `cloud` 后构建。客户端没有演练回退逻辑。

## 图片审核的真实进入条件

`SQUIDDY_MEDIA_ENABLED` 默认 `false`。只在满足以下条件后开启：

- 平台把 `wxa_media_check` 事件送到已隔离的 callback 函数。`SQUIDDY_CALLBACK_SOURCE` 必须来自该平台实际可信上下文观测，不能猜值；代码同时拒绝携带 OPENID、FROM_APPID、`wx_client` 链或 HTTP 来源的事件。
- 不把 `wx_trigger` 当作消息回调来源：它用于定时任务。未知回调入口保持关闭，并在联调时根据官方协议做适配。
- 已验证 `msgSecCheck`、`mediaCheckAsync` 权限和真实返回结构；正常图片、违规图片、超时、重复回调、回调早于入库均有证据。
- 私有原图被解码、限制像素、缩放为 JPEG 并移除 EXIF/GPS；待审图片不能绑定菜谱或获取展示地址。
- 已验证云文件上传与数据库记录之间的故障清理：代码在审核前持久化文件引用，维护任务回收过期无引用图片；若进程在“上传成功、引用落库前”被强杀，需用存储清单与 `private-images/<media-id>.jpg` 核对并回收孤儿文件。该云端强杀演练目前未执行，图片功能保持关闭。

审核回调先写入持久收件表，maintenance 会在 trace 建立后补应用，避免过早回调丢失。结果只允许把 pending 图片推进到审核终态，旧回调不能覆盖终态。

## 通知与分享

模板未配置时，profile 明确返回不可用。开通时配置实际模板 ID 和标题、状态字段名，并逐项核对该账号模板字段类型与长度。用户拒绝订阅不影响业务；未知发送结果标为 unknown，不自动重发。已发出的提醒不能因撤销上桌状态而收回。

朋友邀请使用服务端 HMAC 口令、哈希存储、到期和撤销检查。持有邀请需要先确认加入；公开摘要只含标题和菜名，不提供成员、地址、时间、备注或价格。海报页面与 getUnlimited 接口已接线；SQUIDDY_POSTER_ENABLED 默认关闭，启用前需确认发布路径和 SQUIDDY_CODE_ENV。scene 使用24字符公开分享短码，不含邀请口令。朋友圈入口、真实小程序码与海报扫码仍需账号能力和双端验收；本地海报明确没有扫码凭据。

## 备份与恢复

个人导出是权限过滤后的可读备份，不能冒充完整数据库恢复。运营备份须包含数据库与文件，并按平台备份能力执行。

仓库提供离线一致性格式与独立恢复工具：

```sh
node scripts/backup.cjs backup snapshot.json NEW-backup.json
node scripts/backup.cjs restore NEW-backup.json NEW-isolated-snapshot.json
```

它校验格式和 SHA256，只创建不存在的输出文件，权限0600，不覆盖现有环境。本地测试在独立存储中恢复后重新鉴权回读，源库保持不变。真实云环境的导出、文件恢复和隔离恢复演练仍是上线门槛。备份包含个人数据，应限制访问并设置保留期。
