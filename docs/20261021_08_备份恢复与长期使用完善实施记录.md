# 备份恢复与长期使用完善实施记录

## TL;DR

- 0.5.0增加用户厨房ZIP备份与新厨房恢复，包含完整菜谱、当前权限允许的记录和可选图片；19个原生页面，118项本地回归通过。
- 修复上传者注销导致共享图片断链、累计40场无法继续发布的问题；历史分页，每间厨房最多同时进行40场，历史不自动删除。
- 退出成员立即撤权，耗时个人清理移到可续跑任务；重新加入不会恢复旧饭局权限，旧清理不能删除新加入后创建的数据。
- 反馈增加本人查询状态与回复；运营备份增加加密文件、互斥锁、失败状态与只读健康核查，已实际采集一次25集合备份。
- 真实开发云验证菜谱与饭局导出、新厨房恢复和重复恢复不复制；开发工具原生入口已生成带图ZIP并通过独立CRC校验，JPEG与真实云读取逐字节一致。微信收藏、完整多账号注销、上限规模性能和异常平台审核仍需专项验收。
- 本轮没有连接外部OSS/COS、创建日常调度、启用收费日志或平台回档，也没有提审、正式发布。微信提醒和多人真机仍按既定范围暂缓。

## 部署坐标与行为

沿用既有免费开发云、Nodejs20.19、3秒时限和api/publicRead/platformCallback/maintenance四个函数。四个函数已重新部署；维护触发器保持每5分钟一次。业务身份继续由微信SDK决定，客户端不传入身份或管理员权限。实际环境标识与完整回执只保存在本机忽略目录。

| 位置 | 改前 | 改后 |
|---|---|---|
| domain/media.js、maintenance.js | 注销上传者可能删除共享菜谱所需图片 | 检查厨房封面、菜谱及历史快照引用；仍被有效厨房引用的图片保留并移除上传者归属。无引用才回收；新图片使用引用索引，旧图片保守核查 |
| domain/history.js、service.js | 40场累计上限；读取全部历史 | 只限制40场同时进行；历史按20条翻页，新增记录不使旧游标重复；厨房首页只取有限近期记录 |

## 用户怎样保存和恢复

1. 先选择厨房，再进入“我的 → 隐私与数据 → 完整厨房备份与恢复”。默认包含图片。大文件拆成ZIP分卷，全部分卷保存才是完整副本。
2. 每个文件提供“收藏到微信”和“发送或另存”。收藏调用微信官方addFileToFavorites；由用户在微信界面完成。旧微信不支持时提示发送给自己再收藏。文件生成与收藏完成分别验证。
3. 从微信聊天选择自己的ZIP分卷。校验通过后恢复到一间新厨房；重复导入同一批分卷只补缺少菜谱，不覆盖原厨房。同一批的后续分卷可继续恢复。
4. 图片重新上传并经过真实审核，待审核时保留进度，下次继续。用户也可明确选择仅恢复文字。
5. 历史饭局留在文件中供本卷预览，不重开旧饭局，不恢复旧成员、邀请和公开权限。厨房描述、分类和菜谱可恢复；个人收藏与昵称随备份保留供查阅，不自动覆盖当前账号。

导出遵守当前权限：普通成员得不到内部价格、他人私人备注和不再可访问的旧饭局。导出文件一旦交给微信或其他人就成为独立副本，云端撤权与注销无法召回。离开页面会清除私有预览并停止后续步骤，已经发出的单次请求仍可能完成；恢复幂等记录负责继续时核对。

每卷最多12MiB，通常约8MiB分卷。支持本产品生成的标准未压缩ZIP；不接受任意外来压缩包。文件包含data.json和images/下的受校验图片，普通ZIP工具可打开查看。备份失败时保留已生成部分并明确显示“不能当作完整备份”。

## 当前存储与自有云的接入边界

当前厨房、菜谱、饭局与权限使用CloudBase文档数据库，图片使用CloudBase云存储；[CloudBase官方说明](https://docs.cloudbase.net/storage/introduce)指出其底层基于腾讯云COS。该环境的托管存储不等于用户另一个腾讯云账号下已经连接的COS桶。

阿里云OSS或自有腾讯云COS可以作为异地备份目标。推荐先上传加密运营备份，保留业务主库；需要目标账号、地域、桶名、私有访问权限、保留期与恢复验证后再接入。本轮没有收到这些资源配置，未安装云商SDK、保存密钥或把文件传到外部账号。更换业务图片主存储另需服务端签名、审核读取、删除重试及恢复映射，不能只替换cloud://字符串。

## 运营工具的运行方法

已有`scripts/cloud-backup.cjs`负责两遍只读采集与隔离逻辑恢复；本轮为未知写入增加提交前状态，避免超时后重放。新增工具不开放小程序管理接口：

```sh
npm run backup:run
npm run backup:status
node scripts/backup-run.cjs due
npm run health:cloud
node scripts/support.cjs list NEW-private-receipt.json
node scripts/support.cjs read FEEDBACK_ID NEW-private-ticket.json
node scripts/support.cjs prepare ONE-private-ticket.json reply.txt NEW-private-plan.json
node scripts/support.cjs apply PRIVATE-plan.json NEW-private-state.json
```

官方开发工具CLI需要已登录，WECHATIDE_BIN可指向本机官方可执行文件。所有原始数据与回执存于artifacts，权限0600；本地配置和密钥受Git忽略。运营回复只在可信管理员工具执行，apply产生的原生平台确认需完成后用相同状态文件继续查任务与回读，不重新发写入。

备份使用AES-256-GCM并校验档案内容，32字节密钥位于config/backup.key，与备份分开保管。只复制密文却丢失密钥无法恢复。注意运行目录还保留私有明文采集包与附件，整个artifacts/operator-backups目录不是纯密文目录；异地只复制encrypted-backup.sqb，密钥单独妥善保存。脚本不会自动删除旧成功备份，失败保留前一次成功信息。

`due`是供调度器调用的按UTC日检查入口，不会自行安装周期任务。健康工具只读维护进度、文件队列、清理任务和近期错误；读取上限100，可能截断时返回unknown，不把未知记成零。它不是平台流量SLO、费用告警或自动通知服务。

## 回滚与数据保护

恢复客户端与四函数到上一版本代码不会回退已经写入的数据。新增字段采用兼容缺省；新格式备份只由0.5.0及之后识别。涉及退出成员代次和异步清理的旧代码不理解新撤权语义，不能在清理进行中直接降级后开放业务。需要降级时先停止新写入、保留队列及备份，核对权限和未完成任务再安排恢复；本轮没有执行生产数据回滚。
