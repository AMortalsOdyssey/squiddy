# 免费第一期交付与测试记录

## TL;DR

本篇保留最初本地交付时的证据。后续用户授权的云接入与 mock 验收见 [最新记录](20261021_03_功能补全与界面改版实施记录.md)。

- 十个原生页面与四个云函数入口已经实现免费第一期业务；本轮按用户决定只完成代码和本地测试，不开通云环境。
- 业务测试覆盖真实页面处理器及服务端规则。微信开发者工具也跑通建厨房、添加菜谱、发布、选择、锁单、确认份数、开始制作和上桌。
- 内部价格按接单厨师权限返回；“人数、请求份数、实际份数”分别保存与计算。
- 云端、多手机与正式微信平台能力未验收；不把本地全绿写成可直接上线。

## 部署坐标

本地工程使用 Node.js 24，CI 配置 Node.js 22。微信开发者工具 Stable 2.02.2608080、基础库3.17.4；工具对该基础库有灰度提示。真实AppID仅保存在忽略的本地配置，仓库提供游客模板。云部署次数为0，未购买套餐、未发布小程序。

## 证据与验证范围

2026-10-20最终本地检查：49项测试全部通过，失败0项；主工程和四个云函数分别审计均为0项漏洞。测试日志保存在本机忽略的 artifacts/local-check.log 与 artifacts/audit-all.log。

`npm run check` 执行类型检查、干净构建、Node测试、页面文件检查。测试实际调用 domain、客户端API以及原生页面处理器；WX UI接口与云网络为替身，数据使用独立内存存储。`npm run audit:all` 检查主工程和四个云函数的锁定依赖。

原生工具验收中，一个本地角色代表3人选择番茄炒蛋、请求1份，厨师确认实际2份，内部价格12元得到24元，再推进至已开饭。界面回读明确显示3人、请求1份、制作2份。三角色与弱网的完整自动回归由实际页面处理器驱动，不能称为三个真实微信账号。

依赖修复使用维护中的 lodash set/unset 实现替换旧独立包，并锁定兼容的 axios。测试加载四份实际wx-server-sdk及sharp，验证原型污染防护和图片重编码清除EXIF。SDK能导入不等于真实云请求已通过。

## 偏离与限制

为限制初期存储和事务规模，当前产品上限为5个厨房、每厨30成员、80道菜、40场历史、单餐30道菜、单图2MB。页面会拒绝超过上限，不跳转付费。厨房达到历史上限后，可导出备份并关闭不再使用的厨房，再创建新厨房；不静默删历史。

已截止饭局在服务端读取时转为锁单，写入路径始终独立检查服务端时间。确认计划后、制作开始前允许重新开放并清除旧计划；制作开始后不能解锁。

公开摘要进一步缩减为标题与菜名，不公开日期或成员。通知未知结果不自动重试，以避免重复通知。个人导出用于可读备份；完整恢复工具只在本地隔离环境演练过。图片删除队列尚未清空时，账号注销进度不会提前显示完成。
