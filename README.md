# 鱿鱼须须 · Squiddy

把拿手菜，做给在意的人。一个为家人、朋友组织饭局的原生微信小程序。

当前交付：**免费第一期 0.5.0：用户备份恢复与长期使用完善**。19 个原生页面，覆盖厨房、菜谱、推荐、点菜、掌勺、历史和隐私管理。微信免费开发环境已接通；多人协作用隔离 mock 账号验证。真实多微信按用户决定暂缓；微信提醒因模板为空暂缓，保留页面内进度。腾讯图片审核回调、审核后私有图片读取及开发版小程序码已验证；正式发布未进行。没有支付、餐费或会员购买入口。

## 本地运行

需要 Node.js 22 或更新版本、npm 和微信开发者工具。

```sh
npm ci --ignore-scripts
npm run setup:cloud
npm run check
```

构建生成 `miniprogram/` 和开发者工具配置。用微信开发者工具导入仓库目录，即可运行本地演练。首次不需要云环境；游客模式的可用能力以工具提示为准。自己的 AppID 可以写入 `config/local.json`：

```sh
cp config/local.example.json config/local.json
npm run build
```

保留 `mode: "demo"`，填入自己的 `appid`。本地配置和生成目录已被 Git 忽略。请勿把 AppSecret、云端密钥或个人数据加入仓库。

“我的 → 一起试一顿饭”可以一键准备六道菜、两位已经点菜的朋友，再切换厨师、Alice、Bob 三个演练角色及模拟断网。也可以从空厨房开始手动走完整流程。所有演练数据只在当前设备中；角色切换与模拟审核不会成为真实云端身份或审核结果。

## 能做什么

- 菜谱库与收藏：12道原创家常做法，个人收藏、厨房想吃清单及批量导入；分享文字可整理预览后保存，不自动抓取网页。
- 厨房与菜谱：管理名称、简介、封面、成员角色；自定义分类与排序、食材、分步图片、来源、副标题、规格口味、手动营养记录、供餐人数、上下架和搜索。
- 一起点菜：发布饭局、确认邀请、填写代表人数、请求份数及私人备注，同菜可分别点选多种规格和口味，保留本机草稿并处理提交冲突。
- 帮你搭一桌：按人数、忌口、喜好、耗时、菜类与历史生成不同组合；整套加入会去重，一键提交会替换当前待选并保留备注。
- 掌勺工作台：汇总想吃人数，另行确认实际制作份数；逐菜开始、上桌或说明不做原因，可撤销最近一次制作状态。
- 购物清单：按确认后的实际制作计划合并食材，手填用量、补充采购、勾选和认领；不自动推算克数。
- 饭后反馈：对已上桌的菜留下标签和留言，自己可改，接单厨师可查看本餐反馈。
- 内部参考金额：菜谱默认价、规格价与本餐组合价分开，按整数分计算；朋友、公开摘要和普通成员导出均不返回价格字段。
- 历史与隐私：历史分页、归档、复制菜单、主动公开及撤销摘要、反馈处理结果、账号停用与分批删除；最多同时40场，历史不自动删除。
- 备份与恢复：当前权限允许的完整菜谱、历史与可选图片导出为ZIP，可收藏到微信或另存；恢复菜谱到新厨房，重复继续不复制，图片重新审核，旧成员和邀请不恢复。

例：两位朋友分别代表 2 人和 1 人，各请求 1 份同一道菜。厨师看到 **3 人想吃、请求 2 份**，最终可以决定做 2 份。内部单价 12 元时合计为 24 元，朋友不会看到金额。

## 代码与验证

| 目录              | 用途                                                                    |
| ----------------- | ----------------------------------------------------------------------- |
| `src/`            | 十九个原生页面与 TypeScript 客户端                                      |
| `domain/`         | 鉴权、事务、版本冲突、状态机、价格投影、推荐与清理逻辑                  |
| `cloud/shared/`   | CloudBase 数据适配器、图片处理、审核、通知和定时任务                    |
| `cloudfunctions/` | `api`、`publicRead`、`platformCallback`、`maintenance` 四个独立部署目录 |
| `cloud/`          | 集合清单、拒绝客户端直读写的规则、环境变量模板                          |
| `tests/`          | 业务边界、真实页面处理器、云接口替身、SDK兼容和备份恢复测试             |

```sh
npm run typecheck
npm test
npm run doctor
npm run audit:all
```

`npm run check` 包含类型检查、构建、测试和页面完整性检查。`npm test` 在临时目录构建演练版本并使用独立 mock 数据，不改动当前云端配置或设备数据。CI 在 Linux / Node.js 22 上执行相同检查与依赖审计。`domain/` 与 `cloud/shared/` 在构建时复制进各云函数，不应手改生成副本。云模式不包含演练业务引擎。

当前本地回归为 **120/120 通过**，主工程与四个云函数依赖审计均为 **0项漏洞**（2026-10-21）。

测试替身不能证明 CloudBase 事务、微信身份、订阅消息或真实网络已可用。原生工具本机验收也不能代替两台手机三个账号的验收。
